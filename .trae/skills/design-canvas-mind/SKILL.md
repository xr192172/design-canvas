# design-canvas 心智外衣

给 Agent 穿戴的「工具集认知层」方法论。核心目标：**让 Agent 从头就"知道"这套工具怎么用，而不是每个会话重新发现一遍，更不是为一个愿望手写一套新工具**。这套方法论会被本地 agent 作为底层心智接入，进一步固化。

适用范围：凡是拿到一个愿望，要用 `design-canvas` 这条工具链去实现（画设计图 / 建链 / 查真跑数据 / 对账 / 重构 / 自查）时，先执行本文四段纪律，再动手。

---

## 一、认知注入（每个会话说先）

通用 LLM 的认知里**不天然装着**这套工具的心智，其习惯用法是挂在会话外的。开工前必须把下面三样注入工作记忆，不允许"边做边猜"：

1. **活的 DSL**：当前 feature 的 live 态（`getDSL(feature)` / `/api/load`），而不是脑补一个 fork 版真相。DSL 只有你每次任务都往里写才是活的，不写就只是过期快照。
2. **能力地图**：见第四节，心里有一张"每个愿望 → 该伸手哪个工具"的接线表。
3. **习惯用法**：工具调用走 MCP/HTTP/CLI 三套出口之一，优先即席编排既有工具，再考虑"要不要造新工具"。

## 二、愿望 → 即席编排（先拼，不造）

拿到一个愿望，顺序强制如下：

1. **先想**：已有哪个工具（或哪几个工具的组合）能拼出它？把编排写在脑子里/临时脚本里，**当场跑通**。
2. **只有**：同一编排被**复用 ≥2 次**、而且它是**稳定的流程**（不是一次性愿望），才固化为常驻工具/注册进 `server_registry` 或 `serve` 端点。
3. **只有**：编排极不稳定、每步都是新逻辑，才考虑"另造一个组件/工具"。

> 反例（要警惕的"曲线工具"）：为了"对账这条链"这一个愿望，直接手写 310 行新工具 + 注册 MCP + 开 HTTP 端点 + 写 e2e + 编译 + 提交。五道 ceremony。这就是成本桶的具象。正确做法：先看看 `chain_recon`/`camera_chain_view` 能不能拼，拼不动、又被反复需要，才固化。

## 三、工具自理 reflex（后工具自动前置 + 缓存跳过）

这是本工具集的核心反射，遇到"下游要上游的产物"时无脑执行：

- **后工具自动前置**：下游工具缺前置产物（如宿主节点无 detail 链），不是报错甩锅，而是**自动调上游工具生成**（`chain_recon` 无链时自动调 `deriveDetailChain`）。
- **缓存跳过**：前置产物已存在（命中缓存）即**跳过重复派生**，不浪费；并把"命中即跳过"当常态，不是异常。
- **诚实纪律**：链路无任何真跑事件 → `not_run=true` 明示「先跑一遍再对账」，**绝不伪造事件、不降级冒充成品**。中间产物（骨架/占位）都不是交付物，最终阶段才是。

这套 reflex 的好处：以一次命令驱动整个流水线，心智成本和执行成本都被压到最低。

## 四、能力地图（愿望 → 工具接线）

分层看待（这也是选工具的依据）：

| 层 | 愿望 | 工具 |
|---|---|---|
| 宏观（整项目） | 建底 / 出图 / 全项目对账 | `import_project` → `render_dsl` → `reconcile_effects` |
| **中观（文件/链）** | 按文件/宿主节点「真跑+查数据+对账」 | **`chain_recon`**（本方法论的样板实现） |
| 微观（单函数） | 纯函数子集 / 证据 | `trace_exec` / `trace_evidence` |

对应的 camera 数据线：`log_query`（查事件）→ `judge`（逐事件判定偏差）→ `chain.rebuildChains/matchChainDecl`（重建实测链 + 链路契约匹配）。

**样板**：`chain_recon` 就是把「后工具自动前置 + 缓存跳过 + 一次命令三件事」落地的参考实现。它先看宿主下有没有 detail 链，没有就自动派生（缓存有过就跳过），再自动发现事件文件、按链过滤、judge、rebuild、契约匹配，最后 `not_run` 诚实标注。功能线按"分层 → 复用既有砖 → 才能固化"来的。

## 五、验收 / 自查清单

交付前用下面几问自检，任一问"是"说明又偏了：

- [ ] 我这个愿望，是不是已经能拿既有工具即席拼出来，我却新建了常驻工具？（= 曲线工具）
- [ ] 开工前是否注入了活 DSL + 能力地图，还是直接开写？（= 心智没注入）
- [ ] 下游要上游产物时，我是让它自动前置 + 缓存跳过，还是直接报错？（= 自理 reflex 没触发）
- [ ] 无真数据时，我是否伪造/降级冒充成品？（= 违反诚实纪律）
- [ ] 是否把最终阶段当交付物，而不是停在中间产物（骨架/占位）？

## 给本地 Agent 的接入说明

本 skill 作为**底层认知层**接入 ai-base/agent-shell：加载时把「能力地图 + 自理 reflex + 愿望→编排纪律」注入工作记忆，使本地 agent 不依赖通用 LLM 的临时发挥，天然只会"先拼既有工具、让工具自理"，从根上衰减"心智不足 + 曲线工具"两类成本。接入后，凡是设计画布相关愿望，都先过本 skill 的「先注入 → 先编排 → 才固化 → 诚实交付」流程。
