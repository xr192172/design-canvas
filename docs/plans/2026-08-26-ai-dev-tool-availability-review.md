# 复盘报告：为什么「真实数据当唯一事实源」开发工具链，在开发/重构里没被 AI 实际用上

- **日期**：2026-08-26
- **视角**：开发工具可用性复盘（纯后端工具线，非前端逻辑）
- **结论先行**：不是「缺 skill」，不是「工具没做」；核心是**中观档（按链真跑+查这条链真数据+对该块）没建成「每次重构的一步」**，让我日常够不着真数据，只能回落手填 / 纯函数 / 逆源码折腾。其中「心智」与「成本」两桶我已在上线后修正（见第四节）。

---

## 一、理想闭环 vs 现状

理想：`埋探针 → 程序真跑一轮 → 自动采真实数据 → 展示/验收时从真实数据取（不手填）`

现存基础是**齐的**：
- 真实数据弹药：全量埋探针遗留的 camera 事件流（`events-*.jsonl` / `node.runtime.trace`）
- AI 侧开发工具一套：
  - `reconcile_effects` —— 动静对账（命中转正 / 新观测补录 / 未触发不证伪）
  - `camera_log` —— 按文件查真实运行事件（不传 files 只给偏差）
  - `camera_judge` —— 对真实事件做偏差判定 + 链路契约判定
  - `harvest_closure` —— 拎取一块积木要连根带走什么

然而这批工具在位，AI 在重构里**实际没用上**，反复靠手填 + 纯函数 + 读源码。本报告分三类根因，并标注修正后的占比。

---

## 二、三类根因（初版判断）

### 第一类　心智未编入动作
- **现象**：默认从「读代码、猜」开始，而非「先查真数据 / 真结构」。
- **真实例**：「真实未走通，降级本地模拟」那轮，用一次性脚本 `_probe_diag.py` 抓前端页面、反复核对连的 feature/node 与后端派生 detail 链才对得上；而项目活文档 / DSL 查询本可一步作答。
- **根因（修正后成立）**：DSL 是**扫描 + watch 自动更新**，但「活」的前提是 **AI 每次做任务都把新进展写回 DSL**。一旦不写，它就只是 fork 版的真相 DSL（快照）。`live-doc-sentinel` 是需主动调用的 skill，未强压进上下文 → 缺的是把「先查真数据 + 先写回 DSL」固定成强制动作。

### 第二类　介入成本偏高（初版判断 —— 已被修正，见第四节）
- **初版说法**：动静对账前置链非自动，`import_project → extract_contracts → instrument --effects → 真跑 → 才有 events-*.jsonl`，导致 AI 挑「轻但假」。
- **修正**：这一桶理由不成立，见第四节。

### 第三类　中观缺口 —— 工具真够不着
- **现象**：trace-exec 是纯函数子集，一碰真实 I/O / 外部调用 / 跨模块状态，只能标 `unsupported/error`，给不了真值。
- **根因**：能补真值的唯一来源（camera 事件流）目前接在**宏观/项目级**对账上（整项目 contract vs 全量事件），没有「按这一条链 / 这一块积木」真跑 + 查询 + 对账的轻量档。宏观重、微观假，中间是空的。

---

## 三、因果链 —— 三类实为同一个病

工具承诺「读 DSL / 活文档就行，别读代码」。但**当活文档/DSL 与真代码漂移**时，AI 无法信任 → 退回读源码 → 「退回读源码」恰恰就是「重复来回拉扯」。

```
工具承诺（读活文档） ──漂移──> 无法信任 ──> 退回读源码 ──> 来回拉扯
                                            ▲
                      中观档空缺 = 日常够不着真数据 ┘
```

---

## 四、上线后修正：用户核对后推翻的旧判断

> 用户在评审时指出并纠正两点：

1. **DSL 本就是「扫描 + watch」自动更新的系统**。项目一变就自动触发、重建本地 DSL。所以「活 DSL」不是系统做不到，而是 **AI 的心智是否每次任务都往 DSL 里写**——写了它才是活的，不写它只是 fork 版真相 DSL。→ 强化第一类（心智桶）成立，责任在 AI 的做事方式，并可软件化（管线自动落档）。

2. **「成本高、前置非自动」是错误判断**。前置的扫描是自动的：只要跑过一遍，前置即已具备；其后一条命令即可。**成本桶基本不成立**——问题不是"凑链贵"，而是**链没有编排成「后工具自动调前工具，带缓存，命中即跳过」**。

**修正后的结论**：
- 心智桶（A）✅ 成立 —— 需把「先查真数据 + 先写回 DSL」编成强制动作。
- 成本桶（B）❌ 基本推翻 —— 前置是自动的，一条命令就够了；真正缺的是**链的自动编排 + 缓存跳过**。
- 缺口桶（C）✅ 收敛 —— 中观档没建成「每次重构的一步」。

**落点改写**（结合 A、B、C）：把这条链路做成**可一条命令驱动的流水线**——前工具（扫描/建缓存）自动执行，**后工具自动调用前工具且带缓存、命中缓存即跳过**；DSL 每次由 watch 自动重建、AI 每次做任务主动写回 → 以真数据当基线，漂移即收敛。

## 五、待办边界

| 类别 | 属性 | 该怎么办 |
|------|------|----------|
| 心智（A） | AI 自身可改的做事方式 | 将「先查真数据/真结构 + 先写回 DSL」编成强制动作（流程约束，可软件化为管线每步自动落档） |
| 成本（B） | 已基本撤销 | 不做独立整改，并入 C 的编排设计（后续工具自动前置、缓存命中跳过） |
| 缺口（C） | 唯一需拍板的硬缺口 | 落地中观档：输入 文件/宿主节点 → 输出这条链真跑事件 + 与现状偏差，作为重构前基线 + 重构后验收对照；并接成秒级一条命令 + 缓存跳过 |

**本次约定**：此轮不做工具，仅复盘归档。C 是否落 hand（design-canvas 后端工具线，不动前端）待拍板。

## 六、参考工具 schema

- `reconcile_effects`：读 `<project>/.agent/camera/events-*.jsonl` 与 DSL 契约候选对账；前置链 import → extract → instrument --effects → 运行项目。LLM 不产生事实，判定全部机械。
- `camera_log`：events_file（events.jsonl）+ files 过滤 / all 全量。
- `camera_judge`：events 偏差判定（可带 decls 做链路裁决，text 人类可读）。
- `harvest_closure`：种子文件 import 边传递闭包（importee 方向）。
