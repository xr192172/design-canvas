# design-canvas 功能文档

> 看懂任何一个代码项目。
> 本文档描述产品当前的全部功能、它们之间的协作关系，以及数据如何被共用。

## 1. 产品定位

用户（开发者）导入自己的项目源码，design-canvas 生成**项目地图**，并围绕这份地图提供一整条「理解链」：换角度看结构 → 深入分析病灶 → 生成讲解与演示。用户来这里了解**自己的项目**，而不是了解 design-canvas。

## 2. 核心架构思想：单一数据源，多种投影

所有功能共用同一份数据，区别只是**读取方式与展示策略**：

```
                    ┌─────────────────────────────────────────┐
                    │  设计 DSL（.design-canvas/features/*.json）│
                    │  = 单一事实源（几何层 + 语义层 + source_root）│
                    └───────────────┬─────────────────────────┘
              ┌────────────┬────────┼─────────┬──────────┐
              ▼            ▼        ▼         ▼          ▼
          项目地图      思维导图   分层视图   巨石体检    导览/讲解
         (render)    (mind-map) (arch-layer) (monolith)  (tour)
              │            │        │         │          │
              └── 同一份 DSL 的不同投影，互不冲突，可并存 ──┘
```

四类数据资产：

| 资产 | 位置 | 说明 |
|------|------|------|
| 设计 DSL | `.design-canvas/features/<feature>.json` | 单一事实源。几何层（节点/边/位置）给人看，语义层（文件/符号/依赖）给 AI 用，`source_root` 指向源码快照 |
| 源码快照 | `.design-canvas/projects/<feature>/` | 导入时持久化的源码副本。巨石体检/影响面/一致性等需读源文件的功能以此为基 |
| 实际 DSL | `.design-canvas/live/<feature>.json` | watch_project 从代码实时重建的快照，与设计 DSL 做 diff（设计 vs 实际） |
| 产物注册表 | `output/.registry.json` | 全部已生成产物（地图/报告/导览页…）的登记簿。项目页据此动态渲染，支持人工打标 |

**产物即落盘**：每个功能生成的可视产物（HTML/MD）都写入 `output/` 并自动注册，项目页按「层层递进」分组展示——所以任何功能跑完，结果自动出现在对应项目的页面里。

## 3. 功能总览：层层递进的流水线

功能不是并列的菜单，而是一条递进链：上层消费下层的数据。

### L0 · 导入与项目地图（起点）

| 功能 | 说明 | 通道 |
|------|------|------|
| 项目导入 | 浏览器选源码目录上传 → 源码持久化到 `.design-canvas/projects/` → 解析符号/依赖 → 生成项目地图 | Hub 主页「＋」按钮 / `POST /api/import` |
| 小白视图 | 项目页第一屏，回答新手四问：这是什么软件（一句话+简介）→ 有哪些功能（圆框功能图，人话命名）→ 点圆框看功能详情 → 上手三步 | 项目页默认 / `GET /api/overview` |
| 项目地图（开发者视图） | 全景星空图：目录=星系容器，文件=星点，依赖=连线。点节点逐级下钻 | 项目页「🔓 开发者视图」按钮 / `render_dsl` |
| 项目选择器 | 主页列出已导入项目（语言/文件数/节点数/更新时间），点卡片进项目专属页 | `GET /` |

> **小白视图的数据链**：`derive_feature_tree`（Louvain 调用关系聚类 → 3-8 个功能，带命中率闸门防张冠李戴）→ `derive_mind_map`（功能→社区→文件 树 + LLM 人话描述）→ `getOverview`（组装一句话摘要 + 上手步骤，摘要缓存随 DSL rev 自动失效）。文件平铺形态（早期无源码快照的数据）会诚实降级并引导重新导入。
>
> **LLM 命名与健壮性**：功能名优先 LLM 语义归并（中文名，如"渲染引擎"）；归并失败/超时（分组调用 120s 超时保护）自动降级为"目录分组 + LLM 仅重命名"（45s）；仍失败保持目录名。功能树落盘带 `source: llm|rule` 标记，项目页「✨ AI 优化这段介绍」会把规则版树升级为人话树（描述分批并行生成，单批 60s 超时）。LLM 配置缺省复用 `agent.mmd` 段（OpenAI 兼容），无需单独配置 `llm` 段。

### L1 · 换个角度看（同一数据的视图变换）

| 功能 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 思维导图 | feature | 功能→社区→文件 的树形图 | L3 聚类，看「项目由哪几块业务组成」 |
| 导图问答 | feature + 问题 | 答案（只读 Agent） | 对着思维导图用自然语言提问 |
| 架构分层 | feature | 分层视图（每文件归层） | 按依赖方向自动分层，看「谁在上谁在下」 |
| 布局变换 | feature | 新几何布局 | dag / force / grid 三种，只改几何层不动语义 |
| 设计 vs 实际 | feature | 图级 diff | 设计 DSL 对比代码实时快照，偏差一目了然 |

### L2 · 深入分析（下钻找病灶）

| 功能 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 巨石体检 | feature / project_dir / files | 体检报告 | 行数阈值分档 + 社区聚类，找出巨型文件并给出拆分方向 |
| 拆分任务单 | 单文件路径 | Markdown 任务单 | 把巨石文件的拆分方案写成可直接喂 LLM 执行的任务单 |
| 变更影响面 | feature + 改动文件清单 | 上/下游影响图 | 「改这个文件会波及谁」 |
| 一致性检查 | feature | 设计↔代码偏差 | DSL 声明的 API 与真实代码对不对得上 |
| 语义搜索 | 自然语言 query | 符号 top-k | embedding 向量检索（未配置 LLM 自动降级 FTS） |
| 语言概念 | project_dir | 概念命中清单 | 识别闭包/回调/泛型等语言模式在项目里的分布 |
| 数据流执行 | feature + 节点 + 输入值 | 真实执行结果 | 沿链路真实运行函数，验证理解（非模拟） |

### L3 · 讲解与演示（把理解变成内容）

| 功能 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 学习路径 | feature | 导览步骤序列 | 按依赖拓扑排序生成「先看什么后看什么」 |
| 产物导览 | feature(s) | 播放器页面 | 把项目的全部产物串成可翻页的演示 |
| 科普讲解 | 角色（新人/PM/资深） | 三档讲解文案 | 同一模块按受众换挡，LLM 可再生成 |
| 项目词典 | term | 词条 + 高亮 | 项目术语伪维基，讲解内容中的词条自动高亮互链 |

### L4 · 工程动作（从理解走向修改）

| 功能 | 说明 |
|------|------|
| 脚手架生成 | 按 DSL 语义层生成骨架代码 |
| Camera 插桩 | 运行时异常日志采集 + LLM 判定 |
| watch 实时同步 | 源码一改，缓存/实际 DSL 自动更新 |

## 4. 两个使用通道

| 通道 | 入口 | 适合 |
|------|------|------|
| 人 | Hub（`http://localhost:3000`）：项目选择器 → 项目专属页 → 各产物 | 浏览、验收、演示 |
| AI | MCP 工具集（render_dsl / import_project / check_monolith / derive_mind_map / guided_tour 等 40+） | 生成、迭代、深度分析 |

HTTP API 是两条通道的公共底座，也是**前端可整体替换**的契约层（见 `docs/api.md`）。

## 5. 前端替换契约（给视觉/前端重构的对接说明）

当前 Hub 前端（项目选择器 + 项目页）只是功能壳。重做前端时只需遵守：

1. **数据全部来自 HTTP API**：项目列表 `GET /api/features`，产物 `GET /api/registry`，无任何隐藏状态。
2. **产物即文件**：所有产物是 `output/` 下的静态 HTML/MD，前端只负责枚举与分组展示（当前分组规则：`feature_diagram`→地图，含「树/导图」→换角度，含「分析/拆分/影响」→深入分析，含「讲解/导览/demo」→讲解演示）。
3. **实时刷新用 SSE**：`GET /api/events`，事件 `dsl-changed` / `project-imported`。
4. **写入接口带 Origin 校验**：仅本机 localhost 来源可写。

## 6. 目录速查

```
.design-canvas/
  features/    设计 DSL（每项目一份，单一事实源）
  projects/    导入源码的持久快照（DSL.source_root 指向这里）
  live/        代码实时重建的实际 DSL
output/
  *.html/md    全部产物（自动注册到 .registry.json）
  .registry.json  产物注册表
```
